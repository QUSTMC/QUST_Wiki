## Starlight 内容编辑入门教程

> 本教程适合刚接触 Starlight 的文档作者，带你从零开始学会写页面、用组件、配导航。

---

## 一、先认识你的项目结构

在开始写作之前，先了解一下 Starlight 项目的文件都放在哪里。你不需要记住所有文件，重点关注下面这几个就够了：

```txt
你的项目/
├── astro.config.mjs          # Astro 配置文件（包含 Starlight 集成和侧边栏配置）
├── src/
│   ├── content/
│   │   ├── docs/             # ★ 你的所有文档页面都放在这里
│   │   │   ├── guides/
│   │   │   │   ├── 01-getting-started.md
│   │   │   │   └── 02-advanced.md
│   │   │   └── index.mdx
│   │   ├── i18n/             # 可选：国际化翻译数据
│   │   └── content.config.ts # 内容集合配置文件
│   ├── assets/               # 图片、Logo 等资源
│   └── components/           # 自定义组件
└── public/                   # 静态资源（字体、图标、PDF 等，不会被 Astro 处理）
```

**关键规则**：`src/content/docs/` 里的每一个 `.md` 或 `.mdx` 文件都会自动变成网站上的一个页面。用子文件夹来组织文件，就会自动生成对应的 URL 路径。

举个例子，文件结构这样放：

```txt
src/content/docs/
├── hello-world.md            → your-site.com/hello-world
└── reference/
    └── faq.md                → your-site.com/reference/faq
```

## 二、创建你的第一个页面

在 `src/content/docs/` 下新建一个 `.md` 文件，比如 `my-first-page.md`，然后写上下面的内容：

```markdown
---
title: 我的第一个页面
description: 这是一个示例页面，用来学习 Starlight 的基本写法。
---

这是页面的正文内容。你可以在这里写任何想说的话。
```

**注意**：每个页面都**必须**在文件开头的 `---` 之间提供一个 `title`（标题）。这个标题会显示在页面顶部、浏览器标签页和页面元数据中。

### frontmatter 还能写什么？

`title` 是唯一必填的字段。其他常用字段包括：

```yaml
---
title: 页面标题                    # 必填
description: 页面的简短描述         # 用于 SEO 和搜索结果
slug: custom-url                   # 自定义 URL（可选）
editUrl: https://github.com/...    # 编辑此页面的链接（可选）
tableOfContents: false             # 是否显示右侧目录（默认 true）
---
```

## 三、Markdown 基础写作

Starlight 支持完整的 Markdown 语法。以下是你最常用的几种写法：

### 3.1 文本格式

```markdown
这是 **粗体**，这是 *斜体*，这是 ~~删除线~~。
这是 `行内代码`。
```

### 3.2 标题

**不要用 `#` 写一级标题**。Starlight 会自动把 frontmatter 中的 `title` 作为页面的一级标题。你的正文应该从 `##` 开始：

```markdown
## 二级标题（会出现在右侧目录中）

### 三级标题（也会出现在目录中）

#### 四级标题（不会出现在目录中）
```

### 3.3 链接与图片

```markdown
[链接文字](https://example.com)

![图片描述](./images/screenshot.png)
```

图片放在 `src/content/docs/` 旁边的位置，或者放在 `src/assets/` 里都可以。图片描述（alt text）对屏幕阅读器很重要，**不要省略**。

### 3.4 旁白（Aside）

旁白用来在正文旁边显示辅助信息，是 Starlight 的一个特色功能。语法是用一对 `:::` 包裹内容：

```markdown
:::note
这是一个普通提示。
:::

:::tip
这是一个小技巧。
:::

:::caution
注意！这里可能会踩坑。
:::

:::danger
危险！请谨慎操作。
:::
```

你还可以自定义标题和图标：

```markdown
:::tip[你知道吗？]{icon="heart"}
自定义标题和心形图标。
:::
```

**建议**：`caution` 和 `danger` 不要滥用。如果你发现自己频繁使用它们，可能说明内容需要重新组织一下。

### 3.5 引用和代码块

```markdown
> 这是块引用，通常用来引用其他人的话。

```javascript
// 代码块，开头指定语言
const greeting = "Hello, Starlight!";
```txt
```

## 四、使用 MDX 和组件

当 Markdown 不够用的时候，可以把文件后缀改成 `.mdx`，就能在文档里使用组件了。

### 4.1 在 MDX 中使用内置组件

Starlight 提供了许多内置组件，从 `@astrojs/starlight/components` 包导入即可：

```mdx
---
title: 使用组件
---

import { Card, CardGrid, LinkCard, Tabs, TabItem } from '@astrojs/starlight/components';

<CardGrid>
  <LinkCard
    title="Starlight 官网"
    href="https://starlight.astro.build/"
    description="官方文档和指南"
  />
  <LinkCard
    title="Astro 文档"
    href="https://docs.astro.build/"
    description="Astro 框架的完整文档"
  />
</CardGrid>
```

### 4.2 常用内置组件速查

| 组件 | 用途 | 简单示例 |
| ------ | ------ | ---------- |
| `<Card>` / `<CardGrid>` | 卡片布局 | `<Card title="标题">内容</Card>` |
| `<LinkCard>` | 链接卡片 | `<LinkCard title="..." href="..." />` |
| `<Tabs>` / `<TabItem>` | 标签页切换 | `<Tabs><TabItem label="Tab 1">...</TabItem></Tabs>` |
| `<Steps>` | 步骤列表 | `<Steps><li>第一步</li></Steps>` |
| `<Aside>` | 旁白（等价于 `:::`） | `<Aside type="tip">...</Aside>` |
| `<Badge>` | 徽章标签 | `<Badge text="New" variant="tip" />` |
| `<FileTree>` | 文件树展示 | `<FileTree><ul><li>src/</li></ul></FileTree>` |

### 4.3 组件样式冲突怎么办？

如果组件样式和 Starlight 默认的 Markdown 样式冲突，给组件加上 `not-content` 类就能禁用默认样式：

```mdx
<div class="not-content">
  <!-- 这里的内容不会应用 Starlight 的默认 Markdown 样式 -->
</div>
```

## 五、侧边栏导航配置

默认情况下，Starlight 会根据 `src/content/docs/` 的文件结构自动生成侧边栏。如果需要手动控制，可以在 `astro.config.mjs` 中配置：

```javascript
// astro.config.mjs
import starlight from '@astrojs/starlight';

export default defineConfig({
  integrations: [
    starlight({
      sidebar: [
        {
          label: '入门指南',
          items: [
            { label: '快速开始', slug: 'guides/getting-started' },
            { label: '进阶用法', slug: 'guides/advanced' },
          ],
        },
        {
          label: '参考资料',
          autogenerate: { directory: 'reference' },
        },
      ],
    }),
  ],
});
```

**说明**：

- `slug` 对应 `src/content/docs/` 下的文件路径（不含后缀名）
- `autogenerate` 会自动扫描指定目录下的所有页面
- `label` 是显示在侧边栏中的文字

## 六、自定义页面（进阶）

大多数情况下你只需要写 `.md` 或 `.mdx` 文件就够了。但如果需要完全自定义布局，可以在 `src/pages/` 下创建 `.astro` 文件：

```txt
src/
├── content/docs/           # 常规 Markdown 页面
│   └── hello-world.md
└── pages/
    ├── custom.astro        # 自定义页面
    └── archived.html       # 也可以放 HTML
```

要在自定义页面中使用 Starlight 的布局和样式，用 `<StarlightPage>` 组件包裹内容即可。

---

## 七、常见问题速查

| 问题 | 解决方法 |
| ----- | ---------- |
| 页面没有出现在侧边栏 | 检查文件是否在 `src/content/docs/` 下 |
| 标题显示不对 | 确认 frontmatter 中有 `title` 字段 |
| 图片不显示 | 确认路径正确，图片描述（alt）不能为空 |
| 组件不工作 | 文件后缀必须是 `.mdx`，且组件需要 import |
| 想隐藏右侧目录 | frontmatter 中设置 `tableOfContents: false` |

---

## 总结

写 Starlight 文档的核心就三件事：

1. **在 `src/content/docs/` 里创建 `.md` 或 `.mdx` 文件**，每个文件就是一个页面
2. **用 frontmatter 配置页面元数据**，`title` 是必填的
3. **需要交互组件时用 `.mdx`**，从 `@astrojs/starlight/components` 导入即可

掌握了这些，你就可以开始愉快地写文档了！
